# AI Paralegal (`ai-paralegal`)

Production-ready legal operations platform for legal document ingestion, contract and clause risk analysis, discovery/evidence synthesis, citation-backed research Q&A, legal drafting assistance, and attorney-in-the-loop review with immutable audit logging.

> **Important Legal Disclaimer (Not Legal Advice):**
> All outputs generated by AI Paralegal—including extracted clauses, risk flags, chronologies, research answers, and draft work product—are **AI-assisted legal operations aids** and **do not constitute legal advice or establish an attorney-client relationship**. Every finding, citation, and draft must be independently verified by a licensed attorney before reliance.

---

## Architecture Overview

### Tech Stack
- **Backend:** Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2.x (async), Alembic migrations, Celery + Redis
- **Database & Retrieval:** PostgreSQL 16 + `pgvector` (HNSW semantic index + GIN `tsvector` full-text search fused with Reciprocal Rank Fusion) with seamless SQLite dual-dialect support for zero-infrastructure local dev & offline tests
- **Storage:** Pluggable `StorageBackend` supporting Local Filesystem and S3-compatible object stores (AWS S3 / MinIO / Cloudflare R2)
- **LLM Layer:** Provider-agnostic `ModelRouter` supporting:
  - **Local Ollama** open-weight models: `llama-3.1-8b-instruct`, `qwen-2.5-7b-instruct`, `mistral-nemo-12b`, `deepseek-r1-distill-qwen-8b` (with `<think>` trace stripping)
  - **Cloud Google Gemini:** `gemini-2.5-flash`, `gemini-2.5-pro` via structured JSON mode
  - **Deterministic Offline Mock:** document-aware provider producing verifiable citations and realistic legal analysis without API keys
- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS

## Quick Start

### Option A: Docker Compose (Full Production-Like Stack)
Starts PostgreSQL (`pgvector`), Redis, Alembic migrations + FastAPI API (`http://localhost:8000`), Celery worker, and React/Nginx frontend (`http://localhost:3000`).

```bash
cp .env.example .env
docker compose up --build
```

To also launch a local Ollama container in the stack:

```bash
docker compose --profile ollama up --build
```

### Option B: Local Development (Without Docker)

#### 1. Backend
```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# Initialize local SQLite database via Alembic (or set DATABASE_URL to Postgres)
set DATABASE_URL=sqlite+aiosqlite:///./ai_paralegal.db
alembic upgrade head

uvicorn app.main:app --reload --port 8000
```

#### 2. Frontend
```bash
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173`. Vite proxies `/api/*` directly to `http://127.0.0.1:8000`.

## Sample Workflow Walkthrough

Two realistic legal fixtures are provided in `samples/`:
1. `samples/sample_msa.txt` — Master Services Agreement containing high-risk clauses (uncapped one-sided indemnification, 1-month `$20,000` liability cap, overbroad background IP assignment, perpetual confidentiality, 90-day auto-renewal notice window, and missing data-breach/insurance protections).
2. `samples/sample_discovery_emails.eml` — Multi-message discovery email thread revealing a **commercial contradiction** (`$185,000` annual fee & `12 months` liability cap vs. `$240,000` & `1 month` in the signed MSA) and an **omission** (unproduced Exhibit B SLA schedule and Data Processing Addendum).

### End-to-End Steps in the UI (or via `/api/v1`)
1. **Create a Matter:** Click **New** in the sidebar and create `"Meridian v. Apex Cloud — MSA & Billing Dispute"`.
2. **Ingest Documents:** In **Documents & Provenance**, upload `samples/sample_msa.txt` and `samples/sample_discovery_emails.eml`. Inspect **Chunks** to verify page, paragraph, and section provenance.
3. **Run Contract & Clause Review:** Open **Contract & Clause Risk**, pick your router (`mock`, `ollama`, or `gemini`), and run review. Inspect risk severity cards, missing protections, escalation badges, and expandable verified citations.
4. **Discovery Synthesis, Q&A & Drafting:** Open **Q&A, Synthesis & Drafting**:
   - Run **Discovery Synthesis** to view extracted chronology events, entities, contradictions (`$185k vs $240k`), and missing Exhibit B omissions, or export **Review CSV** / **Chronology Markdown**.
   - Ask citation-grounded questions in **Q&A & Hybrid Search** with explicit **Uncertainties & Missing Context**.
   - Generate an **Internal Legal Ops Memo** in **Citation-Grounded Drafting** (automatically queued for attorney sign-off).
5. **Attorney Review & Audit Trail:** Open **Review Queue & Audit Trail** to edit summaries, attach reviewer notes, approve/flag findings individually or in batch, and inspect logged prompts, models, retrieved spans, and review state transitions.

## Environment Variables

See `.env.example` for defaults:
- `DATABASE_URL`: PostgreSQL async URL (`postgresql+asyncpg://...`) or SQLite (`sqlite+aiosqlite:///./ai_paralegal.db`)
- `TASK_EXECUTION_MODE`: `celery` (Docker Compose), `inline` (local dev / tests without Redis), or `background` (FastAPI `BackgroundTasks`)
- `STORAGE_BACKEND`: `local` (`LOCAL_STORAGE_DIR`) or `s3` (`S3_BUCKET`, `S3_ENDPOINT_URL`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`)
- `LLM_DEFAULT_PROVIDER`: `mock`, `ollama`, or `gemini`
- `LLM_FALLBACK_PROVIDERS`: Comma-separated fallback order (e.g., `ollama,gemini,mock`)
- `LLM_CONFIDENCE_THRESHOLD`, `LLM_GROUNDING_THRESHOLD`, `LLM_ESCALATE_HIGH_RISK`: Escalation thresholds for flagging outputs to human attorneys
- `OLLAMA_BASE_URL`, `OLLAMA_DEFAULT_MODEL`, `OLLAMA_EMBEDDING_MODEL`
- `GEMINI_API_KEY`, `GEMINI_DEFAULT_MODEL`, `GEMINI_EMBEDDING_MODEL`
- `EMBEDDING_PROVIDER`, `EMBEDDING_DIMENSIONS`
