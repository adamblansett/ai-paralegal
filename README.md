# AI Paralegal (`ai-paralegal`)

Production-ready legal operations platform for legal document ingestion (including OCR fallback for scanned PDFs), contract & clause playbook analysis with Word Track Changes redline export, discovery/evidence synthesis, citation-backed research Q&A, legal drafting assistance, and role-based attorney review with immutable audit logging.

> **Important Legal Disclaimer (Not Legal Advice):**
> All outputs generated by AI Paralegal—including extracted clauses, risk flags, proposed redlines, chronologies, research answers, and draft work product—are **AI-assisted legal operations aids** and **do not constitute legal advice or establish an attorney-client relationship**. Every finding, citation, and draft must be independently verified by a licensed attorney before reliance.

## Architecture Overview

### Tech Stack
- **Backend:** Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2.x (async), Alembic migrations, Celery + Redis
- **Auth, RBAC, Multi-Tenancy & Session Hardening:** PBKDF2-HMAC-SHA256 + HS256 JWT bearer authentication with rotated **refresh tokens** (`POST /auth/refresh` + replay detection), immediate **JWT logout revocation** (`POST /auth/logout` jti denylist), enterprise OIDC group-to-role mapping (`GET /auth/providers`, `POST /auth/oidc/exchange`), `Organization` multi-tenant isolation (+ optional PostgreSQL RLS policies in [deploy/sql/rls_policies.sql](deploy/sql/rls_policies.sql)), matter memberships (`users`, `matter_memberships`), and fail-fast production startup checks (`validate_production_security`)
- **Enterprise Scale, Governance & Production Infrastructure:** Distributed Redis ZSET sliding-window rate limiting, Redis Pub/Sub multi-replica SSE event bus (`backend/app/services/events.py`), S3 SSE-KMS encryption & presigned URLs (`GET /documents/{id}/download-url`), litigation **Legal Hold** locks (`POST /matters/{id}/legal-hold`), tamper-evident **SHA-256 hash-chained Audit Logs** (`GET /matters/{id}/audit-logs/verify`), non-root hardened Dockerfiles, `/health/live` & `/health/ready` probes, and Kubernetes deployment manifests in [deploy/k8s/](deploy/k8s/)
- **Enterprise DMS, Escalation Webhooks & Word Add-in:** Pluggable DMS connectors (`mock_dms`, SharePoint, Google Drive, iManage, NetDocuments), SSRF-hardened HMAC-SHA256 Slack/Teams/HTTPS escalation webhooks (`/api/v1/integrations/webhooks`), and Microsoft Word Office.js task-pane add-in (`word-addin/`)
- **Production-Readiness Audit:** Full 4-pillar audit report and verified remediations documented in [docs/PRODUCTION_READINESS_AUDIT.md](docs/PRODUCTION_READINESS_AUDIT.md)
- **Database & Retrieval:** PostgreSQL 16 + `pgvector` (HNSW semantic index + GIN `tsvector` full-text search fused with Reciprocal Rank Fusion) with SQLite dual-dialect support for local dev & offline tests
- **Ingestion, OCR & Source Viewer:** Parsers for PDF, DOCX, TXT, MD, EML threads, and transcripts, upload hardening (extension allowlist, streaming size limit, PDF/DOCX magic-byte verification), pluggable `OCRService` (`tesseract-ocr` + `poppler-utils` in Docker, `mock`, or `disabled`), and interactive **Click-to-Verify Source Viewer** drawer (`GET /documents/{id}/content`) with span scroll & quote highlighting
- **Legal-Ops Safety & Production:** Automated PII detection (`ssn`, `ein`, `email`, `phone`, `bank_account`, Luhn `credit_card`) and privilege classification (`attorney_client`, `work_product`, `confidential`, `privileged_and_confidential`), outbound cloud LLM guardrails (blocks privileged material from cloud providers, redacts PII before Gemini calls), sequential page-level **Bates Stamping** (`POST /matters/{id}/documents/bates-stamp`), and **Privilege Log** export (CSV, JSON, Markdown, DOCX)
- **Playbooks, Risk Matrix & Live SSE:** Reusable contract playbooks (`playbooks` table), native OOXML Word `.docx` Track Changes (`<w:del>` / `<w:ins>`) redline export, batch **Portfolio Risk Matrix** (`POST /matters/{id}/analyses/batch-contract-review`, `GET /matters/{id}/analyses/risk-matrix`), and live Server-Sent Events (`GET /matters/{id}/events`)
- **Observability & Rate Limiting:** Pure ASGI security headers, `X-Request-ID` tracing, sliding-window rate limits on auth & LLM routes, and Prometheus metrics (`GET /metrics`, `GET /api/v1/telemetry/summary`)
- **LLM Layer:** Provider-agnostic `ModelRouter` supporting per-task model routing (`DEFAULT_TASK_MODELS` / `LLM_TASK_ROUTING_JSON`) across local Ollama (`llama-3.1-8b-instruct`, `qwen-2.5-7b-instruct`, `mistral-nemo-12b`, `deepseek-r1-distill-qwen-8b`), cloud Google Gemini (`gemini-2.5-flash`, `gemini-2.5-pro`), and deterministic offline mock mode
- **Frontend & Tests:** React 18, TypeScript, Vite, Tailwind CSS, Vitest + React Testing Library unit suite, and Playwright E2E workflow suite

## Quick Start

### Option A: Docker Compose (Full Production-Like Stack)
Starts PostgreSQL (`pgvector`), Redis, Alembic migrations + FastAPI API (`http://localhost:8000`, with Tesseract OCR pre-installed), Celery worker, and React/Nginx frontend (`http://localhost:3000`).

```bash
cp .env.example .env
docker compose up --build
```

To also launch a local Ollama container in the stack:

```bash
docker compose --profile ollama up --build
```

### Option B: Local Development (Without Docker)

#### 1. Backend
```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# Initialize local SQLite database via Alembic (or set DATABASE_URL to Postgres)
set DATABASE_URL=sqlite+aiosqlite:///./ai_paralegal.db
alembic upgrade head

uvicorn app.main:app --reload --port 8000
```

#### 2. Frontend
```bash
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173`. Vite proxies `/api/*` directly to `http://127.0.0.1:8000`.

## Authentication, RBAC & Demo Accounts

When `AUTH_AUTO_SEED_DEMO_USERS=true` (development default), startup seeds four demo firm roles (password `ParalegalDemo2026!`) plus the **Commercial SaaS / MSA Standard Playbook**:

| Role | Demo Email | Capabilities |
| --- | --- | --- |
| `partner` | `partner@firm.example.com` | Full visibility across all firm matters, team membership management, finding approvals, playbook CRUD |
| `associate` | `associate@firm.example.com` | Access to owned/assigned matters, document ingestion, analysis, playbook creation, attorney finding approvals |
| `paralegal` | `paralegal@firm.example.com` | Access to owned/assigned matters, document ingestion, analysis, flagging findings (cannot set `approved`) |
| `auditor` | `auditor@firm.example.com` | Read-only compliance inspection across matters, findings, exports, and immutable audit logs |

Every `Review` action and `AuditLog` entry derives `reviewer_name` and `actor_id` authoritatively from the signed JWT user identity.

## Sample Workflow Walkthrough

Two legal fixtures are provided in `samples/`:
1. `samples/sample_msa.txt` — Master Services Agreement with high-risk clauses and missing security/insurance protections.
2. `samples/sample_discovery_emails.eml` — Discovery email thread with `$185k` vs `$240k` fee/cap contradictions and missing Exhibit B / DPA omissions.

### End-to-End Steps
1. **Sign In & Create a Matter:** Sign in via the UI (e.g., Partner demo button) and create `"Meridian v. Apex Cloud — MSA & Billing Dispute"`. Use **Team Access** to assign associates/paralegals.
2. **Ingest Documents & Inspect Provenance:** Upload `samples/sample_msa.txt` and `samples/sample_discovery_emails.eml` in **Documents & Provenance**. Scanned PDFs automatically trigger `OCRService` and display OCR status badges.
3. **Playbook Contract Review & Word Redline Export:** Open **Contract & Clause Risk**, pick a playbook (`Default Firm Playbook` or create a custom one), run review, inspect side-by-side **Original Contract Language vs. Proposed Playbook Fallback Redline**, and download **Word Redline (.docx)** with native Track Changes.
4. **Discovery Synthesis, Q&A & Drafting:** Run **Discovery Synthesis**, download Review CSV / Chronology Markdown, run citation-grounded Q&A, or draft an internal memo queued for attorney sign-off.
5. **Attorney Review & Audit Trail:** Approve or flag findings in **Review Queue & Audit Trail** and inspect logged prompts, models, retrieved spans, and review state transitions.

## Enterprise Governance, Observability & Deployment Packaging

- **PostgreSQL RLS Enforcement ([deploy/sql/rls_policies.sql](deploy/sql/rls_policies.sql), [backend/app/db/rls.py](backend/app/db/rls.py)):** Authenticated PostgreSQL sessions automatically execute `set_config('app.current_organization_id', ..., true)` with `after_begin` transaction propagation alongside `FORCE ROW LEVEL SECURITY` policies.
- **Cryptographic OIDC JWKS Verification & Role Sync ([backend/app/core/oidc.py](backend/app/core/oidc.py)):** Verifies RS256/RS384/RS512 (plus ES256–ES512 when `cryptography` is installed) OIDC ID tokens against cached JWKS keys with automatic key-rotation refresh and on-login group-to-role synchronization.
- **Automated Retention & Legal-Hold Purge Worker ([backend/app/services/retention.py](backend/app/services/retention.py)):** Celery Beat schedules periodic `ai_paralegal.retention_sweep` jobs (plus on-demand partner preview/execute in the **Admin & Integrations** modal) that purge expired non-held documents while preserving items under active Legal Hold and recording hash-chained `AuditLog` entries.
- **OpenTelemetry, Grafana & Helm ([deploy/monitoring/](deploy/monitoring/), [deploy/helm/ai-paralegal/](deploy/helm/ai-paralegal/)):** W3C `traceparent` propagation across FastAPI, LLM routing, and Celery tasks, paired with Prometheus alerting rules, Grafana dashboard JSON, and a parameterized Helm v3 chart.
