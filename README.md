# AI Paralegal (`ai-paralegal`)

Production-ready legal operations platform for legal document ingestion (including OCR fallback for scanned PDFs), contract & clause playbook analysis with Word Track Changes redline export, discovery/evidence synthesis, citation-backed research Q&A, legal drafting assistance, and role-based attorney review with immutable audit logging.

> **Important Legal Disclaimer (Not Legal Advice):**
> All outputs generated by AI Paralegal—including extracted clauses, risk flags, proposed redlines, chronologies, research answers, and draft work product—are **AI-assisted legal operations aids** and **do not constitute legal advice or establish an attorney-client relationship**. Every finding, citation, and draft must be independently verified by a licensed attorney before reliance.

---

## Architecture Overview

### Tech Stack
- **Backend:** Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2.x (async), Alembic migrations, Celery + Redis
- **Auth & RBAC:** PBKDF2-HMAC-SHA256 + HS256 JWT bearer authentication (`users`, `matter_memberships`), matter-level isolation, firm roles (`partner`, `associate`, `paralegal`, `auditor`), and authoritative cryptographic actor/reviewer attribution
- **Database & Retrieval:** PostgreSQL 16 + `pgvector` (HNSW semantic index + GIN `tsvector` full-text search fused with Reciprocal Rank Fusion) with SQLite dual-dialect support for local dev & offline tests
- **Ingestion & OCR:** Parsers for PDF, DOCX, TXT, MD, EML threads, and transcripts, plus pluggable `OCRService` (`tesseract-ocr` + `poppler-utils` in Docker, `mock`, or `disabled`) for image-only scanned PDFs
- **Playbooks & Redlines:** Reusable contract playbooks (`playbooks` table with seeded Commercial SaaS/MSA baseline rules + fallback clause text) and native OOXML Word `.docx` Track Changes (`<w:del>` / `<w:ins>`) redline export
- **LLM Layer:** Provider-agnostic `ModelRouter` supporting:
  - **Local Ollama:** `llama-3.1-8b-instruct`, `qwen-2.5-7b-instruct`, `mistral-nemo-12b`, `deepseek-r1-distill-qwen-8b` (with `<think>` trace stripping)
  - **Cloud Google Gemini:** `gemini-2.5-flash`, `gemini-2.5-pro` via structured JSON mode
  - **Deterministic Offline Mock:** document-aware provider producing verifiable citations without external API keys
- **Frontend:** React 18, TypeScript, Vite, Tailwind CSS

## Quick Start

### Option A: Docker Compose (Full Production-Like Stack)
Starts PostgreSQL (`pgvector`), Redis, Alembic migrations + FastAPI API (`http://localhost:8000`, with Tesseract OCR pre-installed), Celery worker, and React/Nginx frontend (`http://localhost:3000`).

```bash
cp .env.example .env
docker compose up --build
```

To also launch a local Ollama container in the stack:

```bash
docker compose --profile ollama up --build
```

### Option B: Local Development (Without Docker)

#### 1. Backend
```bash
cd backend
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -e ".[dev]"

# Initialize local SQLite database via Alembic (or set DATABASE_URL to Postgres)
set DATABASE_URL=sqlite+aiosqlite:///./ai_paralegal.db
alembic upgrade head

uvicorn app.main:app --reload --port 8000
```

#### 2. Frontend
```bash
cd frontend
npm install
npm run dev
```
Open `http://localhost:5173`. Vite proxies `/api/*` directly to `http://127.0.0.1:8000`.

## Authentication, RBAC & Demo Accounts

When `AUTH_AUTO_SEED_DEMO_USERS=true` (development default), startup seeds four demo firm roles (password `ParalegalDemo2026!`) plus the **Commercial SaaS / MSA Standard Playbook**:

| Role | Demo Email | Capabilities |
| --- | --- | --- |
| `partner` | `partner@firm.example.com` | Full visibility across all firm matters, team membership management, finding approvals, playbook CRUD |
| `associate` | `associate@firm.example.com` | Access to owned/assigned matters, document ingestion, analysis, playbook creation, attorney finding approvals |
| `paralegal` | `paralegal@firm.example.com` | Access to owned/assigned matters, document ingestion, analysis, flagging findings (cannot set `approved`) |
| `auditor` | `auditor@firm.example.com` | Read-only compliance inspection across matters, findings, exports, and immutable audit logs |

Every `Review` action and `AuditLog` entry derives `reviewer_name` and `actor_id` authoritatively from the signed JWT user identity.

## Sample Workflow Walkthrough

Two legal fixtures are provided in `samples/`:
1. `samples/sample_msa.txt` — Master Services Agreement with high-risk clauses and missing security/insurance protections.
2. `samples/sample_discovery_emails.eml` — Discovery email thread with `$185k` vs `$240k` fee/cap contradictions and missing Exhibit B / DPA omissions.

### End-to-End Steps
1. **Sign In & Create a Matter:** Sign in via the UI (e.g., Partner demo button) and create `"Meridian v. Apex Cloud — MSA & Billing Dispute"`. Use **Team Access** to assign associates/paralegals.
2. **Ingest Documents & Inspect Provenance:** Upload `samples/sample_msa.txt` and `samples/sample_discovery_emails.eml` in **Documents & Provenance**. Scanned PDFs automatically trigger `OCRService` and display OCR status badges.
3. **Playbook Contract Review & Word Redline Export:** Open **Contract & Clause Risk**, pick a playbook (`Default Firm Playbook` or create a custom one), run review, inspect side-by-side **Original Contract Language vs. Proposed Playbook Fallback Redline**, and download **Word Redline (.docx)** with native Track Changes.
4. **Discovery Synthesis, Q&A & Drafting:** Run **Discovery Synthesis**, download Review CSV / Chronology Markdown, run citation-grounded Q&A, or draft an internal memo queued for attorney sign-off.
5. **Attorney Review & Audit Trail:** Approve or flag findings in **Review Queue & Audit Trail** and inspect logged prompts, models, retrieved spans, and review state transitions.
